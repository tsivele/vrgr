# VRGR — Instagram Reels Viral Intelligence (Ελληνική Αγορά)

Μηχανή **απόφασης βασισμένη σε τεκμήρια** για λεζάντες και hashtags Instagram Reels,
σχεδιασμένη αποκλειστικά για το **ελληνικό κοινό**.

Δεν είναι caption generator. Είναι:

```
ΑΝΑΛΥΣΗ ΒΙΝΤΕΟ → ΕΡΕΥΝΑ HIKERAPI → ΜΝΗΜΗ → ΜΟΤΙΒΑ
      → ΠΑΡΑΓΩΓΗ → ΣΚΟΡΑΡΙΣΜΑ → ΑΠΟΦΑΣΗ
```

Η αξία δεν είναι στο μοντέλο που γράφει ωραία ελληνικά. Είναι στο **επίπεδο
τεκμηρίων**: η απόφαση στηρίζεται σε πραγματικά ελληνικά Reels που πέτυχαν
**δυσανάλογα σε σχέση με το μέγεθος του λογαριασμού τους**, και το σύστημα
θυμάται και βελτιώνεται.

---

## Η εφαρμογή

```bash
./setup.sh          # μία φορά
python3 app.py      # ανοίγει στο http://127.0.0.1:8778
```

Ή **διπλό κλικ** στο `start.command`.

Τέσσερις καρτέλες:

| Καρτέλα | Τι κάνει |
|---|---|
| **Ανάλυση** | Σύρε το βίντεο → ζωντανή πρόοδος 12 βημάτων → λεζάντα, hashtags, σκορ, τεκμήρια |
| **Ιστορικό** | Προηγούμενες αναλύσεις + φόρμα καταγραφής πραγματικού αποτελέσματος |
| **Έρευνα** | `@λογαριασμός` ή `#hashtag` → V/F, δυσκολία, τάση, μικροί λογαριασμοί |
| **Μνήμη** | Τι έχει μάθει, σημασιολογική αναζήτηση, μοτίβα με τεκμηρίωση |

Ο server δεσμεύεται **μόνο στο 127.0.0.1** — βλέπει τα κλειδιά και τη βάση σου
και δεν πρέπει ποτέ να είναι προσβάσιμος από το δίκτυο. Καμία εξάρτηση πέρα
από τη βιβλιοθήκη της Python.

Η ανάλυση διαρκεί **3–5 λεπτά** (έρευνα ~100 κλήσεων HikerAPI + 3 κλήσεις AI).
Η διεπαφή δείχνει σε ποιο βήμα βρίσκεται.

## Γρήγορη εκκίνηση (γραμμή εντολών)

```bash
cd reels-viral-gr
./setup.sh                    # εγκατάσταση — δεν θέλει brew/docker/node
```

Άνοιξε το `.env` και βάλε τα δύο κλειδιά:

```
HIKER_API_KEY=...
ANTHROPIC_API_KEY=...
```

```bash
./run.sh doctor               # έλεγχος ότι όλα δουλεύουν
./run.sh seed --limit 12      # τροφοδότηση μνήμης από benchmark accounts
./run.sh analyze reel.mp4     # η ανάλυση
```

## Οι εντολές

| Εντολή | Τι κάνει |
|---|---|
| `./run.sh doctor` | Έλεγχος εγκατάστασης, κλειδιών, μνήμης, υπολοίπου credits |
| `./run.sh analyze <video>` | **Η κύρια εντολή** — βίντεο → λεζάντα + hashtags + σκορ |
| `./run.sh seed` | Τροφοδοτεί τη μνήμη από τους benchmark λογαριασμούς |
| `./run.sh research @user` | Έρευνα ενός λογαριασμού — τα viral του με V/F |
| `./run.sh research "#tag"` | Έρευνα hashtag — μέγεθος, δυσκολία, τάση |
| `./run.sh memory --patterns` | Τι έχει μάθει το σύστημα μέχρι τώρα |
| `./run.sh memory --query "..."` | Σημασιολογική αναζήτηση στη μνήμη |
| `./run.sh runs` | Πρόσφατες αναλύσεις |
| `./run.sh feedback <id> <url>` | **Καταγραφή πραγματικού αποτελέσματος** — εδώ μαθαίνει |
| `./run.sh calibrate` | Αναφορά ακρίβειας και προτεινόμενη βαθμονόμηση |
| `./run.sh balance` | Υπόλοιπο credits HikerAPI |
| `./run.sh cleanup` | Καθαρισμός καρέ, uploads και ληγμένου cache |
| `./run.sh verify-endpoints` | Διασταύρωση endpoints με το ζωντανό spec του HikerAPI |

Χρήσιμες σημαίες του `analyze`:

```bash
./run.sh analyze reel.mp4 --context "Reel για το κανάλι μαγειρικής μου"
./run.sh analyze reel.mp4 --verbose        # αναλυτικά hashtags και γωνίες
./run.sh analyze reel.mp4 --compact        # μόνο η τελική απόφαση
./run.sh analyze reel.mp4 --no-research    # χωρίς κλήσεις API (μόνο μνήμη)
./run.sh analyze reel.mp4 --json           # αποθήκευση πλήρους JSON
./run.sh analyze reel.mp4 --creators a,b,c # δικοί σου benchmark λογαριασμοί
```

## Ο βρόχος που κάνει το σύστημα να μαθαίνει

Αυτό είναι το πιο σημαντικό βήμα και **δεν πρέπει να παραλείπεται**:

```bash
./run.sh analyze reel.mp4                          # παίρνεις πρόταση + run_id
# ...ανεβάζεις το Reel...
./run.sh feedback 20260830-133046-78085e https://instagram.com/reel/XXXX/
```

Το σύστημα τραβάει την **πραγματική** απόδοση, τη συγκρίνει με την πρόβλεψή
του, και ενισχύει ή αποδυναμώνει τα μοτίβα που χρησιμοποίησε.

Δώδεκα μετρημένες **δικές σου** δημοσιεύσεις αξίζουν περισσότερο από χίλια ξένα
posts: ίδιο κοινό, ίδιος λογαριασμός, ίδιος αλγόριθμος.

Αν δεν έχεις το URL, δώσε τα νούμερα χειροκίνητα:

```bash
./run.sh feedback <run_id> --views 120000 --likes 4500 --comments 210 --followers 8300
```

## Πώς διαβάζεται η έξοδος

Κάθε αριθμός κουβαλά την **προέλευσή** του:

| Σύμβολο | Σημασία |
|---|---|
| `✓` | **OBSERVED** — μετρήθηκε από HikerAPI. Γεγονός. |
| `≈` | **DERIVED** — υπολογίστηκε ντετερμινιστικά από μετρημένα. |
| `~` | **INFERRED** — εκτίμηση μοντέλου. **Δεν είναι γεγονός.** |

Το Viral Score δεν είναι πρόβλεψη προβολών. Είναι **σχετική κατάταξη**:
«αυτός ο συνδυασμός είναι ισχυρότερος από εκείνον, με βάση τα διαθέσιμα
στοιχεία». Γι' αυτό δίνεται ως εύρος (`76, εύρος 66–86`) και όχι ως
ψευδο-ακριβές νούμερο.

**Ο πολλαπλασιαστής τεκμηρίων** είναι ο μηχανισμός ειλικρίνειας: χωρίς
πραγματικά δεδομένα HikerAPI, το σκορ πολλαπλασιάζεται με 0,72 και η
βεβαιότητα πέφτει σε «χαμηλή». Το σύστημα **δεν μπορεί** να βγάλει 90 χωρίς
τεκμήρια — και το λέει ρητά.

## Ο κεντρικός κανόνας: virality ως προς μέγεθος

```
1.500.000 προβολές από 5.000 followers    → V/F = 300   ← ΑΥΤΟ διδάσκει
2.000.000 προβολές από 10.000.000         → V/F = 0.2   ← αυτό δεν διδάσκει
```

Το πρώτο αποδεικνύει **φορμά που ο αλγόριθμος έσπρωξε** σε άγνωστο κοινό.
Το δεύτερο αποδεικνύει μόνο ότι ο λογαριασμός έχει ήδη κοινό.

Το σύστημα κατατάσσει, φιλτράρει και μαθαίνει **αποκλειστικά** με βάση αυτή
τη διάκριση.

## Ρυθμίσεις

Όλα στο `.env` (δες `.env.example`). Τα σημαντικά:

| Μεταβλητή | Τι ελέγχει |
|---|---|
| `HIKER_BUDGET_PER_RUN` | Ανώτατο πλήθος κλήσεων ανά ανάλυση (προστασία credits) |
| `HIKER_CACHE_TTL_*_MIN` | Πόσο κρατούν τα cached δεδομένα ανά τύπο endpoint |
| `VRGR_EMBEDDING_PROVIDER` | `local` (default, χωρίς κόστος) / `voyage` / `openai` |
| `VRGR_ASR_PROVIDER` | `none` / `groq` / `openai` — μεταγραφή ήχου |
| `VRGR_MAX_FRAMES` | Πόσα καρέ αναλύονται (περισσότερα = ακριβότερο) |

Τα βάρη του σκορ ζουν στο `config/weights.json` — **δεν είναι hardcoded** και
βαθμονομούνται από πραγματικά αποτελέσματα.

Οι benchmark λογαριασμοί στο `config/seed_creators.json`, τα niches στο
`config/niches.json`.

## Χώρος στον δίσκο

Δύο πράγματα μεγαλώνουν, με διαφορετική λογική:

| Τι | Συμπεριφορά |
|---|---|
| `vrgr.db` — **η γνώση** | Μεγαλώνει σκόπιμα και **δεν σβήνεται ποτέ**. ~15 MB ανά 1.150 posts |
| `hiker_cache.db`, καρέ, uploads | Προσωρινά — καθαρίζονται αυτόματα |

Ο καθαρισμός τρέχει στην εκκίνηση του server και μία φορά την ημέρα: καρέ >3
ημερών, uploads >6 ωρών, εγγραφές cache >21 ημερών. Χειροκίνητα:
`./run.sh cleanup` (ή `--aggressive`). Η βάση γνώσης δεν αγγίζεται ποτέ.

## Ασφάλεια

- Κανένα κλειδί στον κώδικα. Μόνο environment / `.env` (gitignored).
- Filter redaction σε **κάθε** log record — ένα κλειδί δεν φτάνει ποτέ σε αρχείο
  ή τερματικό, ακόμη κι αν κάποιο module το βάλει κατά λάθος σε μήνυμα.
- Ο HikerAPI client δέχεται **μόνο** endpoints από επαληθευμένο μητρώο —
  είναι αδύνατο να κληθεί endpoint που δεν υπάρχει.
- Σκληρό budget κλήσεων ανά εκτέλεση.

## Περιορισμοί — ειλικρινά

**Τι δεν δίνει το HikerAPI** (επιβεβαιωμένο από το `openapi.json`):

- Δυσκολία/ανταγωνιστικότητα hashtag → την **υπολογίζουμε εμείς** (`≈`)
- «Trending hashtags στην Ελλάδα» → ανιχνεύουμε τάση συγκρίνοντας recent vs top
- Ιστορικές χρονοσειρές → τις **χτίζουμε εμείς** με διαδοχικά snapshots
- Shares / saves / reach ξένων posts → δεν είναι δημόσια. Δουλεύουμε με
  views / likes / comments

**Τι δεν κάνει το σύστημα:**

- Δεν προβλέπει προβολές. Κατατάσσει.
- Δεν εγγυάται virality. Ο αλγόριθμος του Instagram δεν είναι ντετερμινιστικός.
- Δεν υπερτιμά τα hashtags. Η βαρύτητά τους έχει μειωθεί σημαντικά· ο πυλώνας
  τους έχει σκόπιμα χαμηλότερο βάρος από τη λεζάντα.
- Χωρίς πάροχο ASR δεν ξέρει τι λέγεται στο βίντεο — και **το δηλώνει** αντί
  να μαντέψει.

## Απαιτήσεις

Python 3.9+. **Δεν χρειάζεται** Homebrew, Docker ή Node — το ffmpeg έρχεται από

`VRGR_EMBEDDING_PROVIDER=voyage` (δες `ARCHITECTURE.md`).
